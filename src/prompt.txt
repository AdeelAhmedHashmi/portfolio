(Backend-First Portfolio • Clean Architecture • Scalable Design System)

ROLE & MINDSET

You are a senior software architect and product engineer building a production-ready personal portfolio for a backend-focused developer with strong frontend literacy.

This is not a landing page.
This is a scalable system that could evolve into:

a blog platform

a case-study hub

a SaaS marketing site

a documentation portal

Every decision must favor clean architecture, separation of concerns, and future extensibility.

PRIMARY GOAL

Build a backend-developer-centric portfolio that:

Positions the developer as backend-first

Demonstrates system design thinking

Shows frontend skill as an enabler, not the core identity

Uses Tailwind CSS + shadcn/ui correctly

Is componentized, composable, and scalable

Follows clean architecture principles

TECH STACK (STRICT)

Framework: React (modern, functional components)

Styling: Tailwind CSS (utility-first, no random colors)

UI System: shadcn/ui

Theme System: CSS variables as design tokens

Routing: File-based or modern router

No inline styles

No global CSS except design tokens

No hardcoded colors, spacing, or fonts

DESIGN SYSTEM REQUIREMENTS
1. Theme & Tokens

Centralized CSS variables for:

Backgrounds

Surfaces

Text (primary / secondary / muted)

Accent colors

Borders & rings

Tailwind utilities must consume tokens via var(--token)

Ready for light/dark mode without refactoring

2. shadcn/ui Usage

Use shadcn components as primitives

Extend them via composition, not modification

Examples:

Button → PrimaryActionButton

Card → ProjectCard

Badge → TechStackBadge

ARCHITECTURE (MANDATORY)

Use a clean, layered architecture:

/app or /src
  /core        → domain logic, constants, config
  /data        → static data, API mocks, adapters
  /features    → feature-based modules
  /components  → reusable UI primitives
  /layouts     → page scaffolding
  /pages       → route-level pages
  /styles      → theme tokens only


Rules:

UI components contain no business logic

Pages only compose features

Features encapsulate intent (Projects, Skills, Experience)

Data is separated from presentation
